**Six of the OCCM parsers can be adapted to emit HT-shaped rows**, covering
roughly **77 of the 136 HT-positional files (57%)**:

|---|---:|

| `iberia_listado.py` | 3 |

The column schema differs (HT carries `TASK_TYPE`, `INTERVAL`, `LAST_DONE_DATE`,
`NEXT_DUE_DATE`, `REMAINING_FH/FC/DAYS`; no TSN/CSN in the OCCM sense) but the
row anchor and layout are identical.

   ceiling as the OCCM side; defer until 1-6 land.

Estimated coverage after steps 1–6: ~**95 of 136 HT-positional files**
(~70%) clean before any new ground-up variant work beyond #3 and #4.

## Schema sketch for `ht_positions.sqlite`

Mirror `positions.sqlite` but with HT-shaped columns:

```
ht_positions
  id, source_file, variant, aircraft_key, aircraft_key_source,
  registration, msn, family, family_confidence,
  report_date, report_date_iso,
  ata, position, position_source,
  description, part_number, serial_number,
  task_type, interval_fh, interval_fc, interval_days,
  last_done_date, last_done_fh, last_done_fc,
  next_due_date, next_due_fh, next_due_fc,
  remaining_fh, remaining_fc, remaining_days,
  row_issues, page
```

`aircraft_key` joins to `positions.aircraft_key` so OCCM + HT data link on the
same airframe (drives the sextant cross-family comparisons).
